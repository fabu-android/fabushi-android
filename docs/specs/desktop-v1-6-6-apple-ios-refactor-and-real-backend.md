**5 Mandatory Anti-Flicker Reconciliation Rules**:
1. **Single-apply, zero feedback loop**: Separate local UI application (`applyLocal`) from user-initiated server dispatch so syncing server state NEVER re-enqueues a pin toggle back to the server.
2. **Atomic multi-surface update**: Toggling pin/mute for `chat_id` atomically updates (a) the chat list item, (b) the active chat header/menu flag, and (c) the cached rich chat metadata map BEFORE dispatching `POST /api/v1/chats/{chat_id}/pin`.
3. **Never bitwise-OR stale flags**: Always read the authoritative boolean flag directly (`dialog.isPinned`), NEVER `remote.isPinned || local.isPinned` (which makes unpinning impossible).
4. **Fail-closed rollback**: On network/4xx/5xx failure, revert optimistic flags in RAM and SQLite write-through cache and show an explicit error toast/banner.
5. **In-flight mutation guard**: Guard `mergeServerChats` / `fetchServerMessagesForChat` with `SessionRequestFence` + an in-flight chat/message mutation set so concurrent polls never clobber an in-flight toggle.

### 8.5 WebSocket Protocol (`/api/v1/ws`) & Complete 27-Variant `UpdateEvent` Catalog

- **URL & Auth**: Derive `ws://` / `wss://` from configured endpoint and connect to `/api/v1/ws?token=<URLEncoder.encode(token, UTF_8)>` (also attaching `Authorization: Bearer <token>` header).
- **Reconnect, Backoff & Lifecycle**:
  - **HTTP `401 Unauthorized`**: Immediately transition to offline/unauthorized state, stop reconnect loop (zero infinite retry spin on revoked tokens), and prompt re-authentication.
  - **Jittered Exponential Backoff**: `base_ms = (1000 * 2^(attempt.min(5))).min(30_000)` (`2s, 4s, 8s, 16s, 30s, ...`), multiplied by uniform random jitter in `[0.75, 1.25]`, clamped to `[500ms, 30_000ms]`.
  - **Generation Fence**: Increment `SessionRequestFence` generation on stop/sign-out/account-switch; drop all callbacks from stale generations.
  - **PTS Gap Recovery**: On reconnect, invoke `/api/v1/sync/difference` (or `WsClientFrame::Sync`) for tracked `chat_pts` so missed messages/updates reconcile cleanly.
- **Wire Envelopes (`#[serde(tag = "type", content = "payload")]`)**:
  - **`WsClientFrame` (16 variants)**: `Ping`, `Sync`, `SendMessage`, `EditMessage`, `DeleteMessages`, `SendReaction`, `ReadHistory`, `SendTyping`, `SubscribeChat`, `UnsubscribeChat`, `VotePoll`, `CallSignal`, `AckUpdates`, `MiniAppWebMcpResult`, `MiniAppTakeoverState`, `CodingHostEvent`.
  - **`WsServerFrame` (6 variants)**: `Pong`, `Update(UpdateEvent)`, `PtsPush(PtsUpdate)`, `SyncDiff`, `Ack`, `Error`.
- **All 27 `UpdateEvent` Variants (`#[serde(tag = "type", content = "data")]`)**:

## 10. Failure modes and edge cases

- **Network Offline / Server 5xx / 403 on Mutations**: Pin/unpin, mute, archive, message edit/delete/reaction, bot creation, computer exec, and assist actions MUST roll back optimistic UI/SQLite state and display an actionable error message — never silently pretend success.
- **WebSocket `401 Unauthorized` vs Transient Drop**: `401` MUST immediately halt reconnect backoff and prompt re-login; transient socket drops MUST retry with jittered exponential backoff (`[500ms, 30_000ms]`), obey `SessionRequestFence` generation, and run PTS `/api/v1/sync/difference` on reconnect.
- **Concurrent Sync Overwriting In-Flight Pin/Mute**: Protected by `SessionRequestFence` + in-flight mutation tracking and single-apply anti-flicker reconciliation (never bitwise-ORing stale flags).
- **Media-Only Messages (`text == ""`)**: History/WS parsers MUST retain media-only messages (photos, voice notes, video notes, files, polls, stickers) instead of skipping blank `text`.
- **Android Permission Denial (`RECORD_AUDIO`, Location, Accessibility)**: Denied mic MUST block recording (no fake waveform); denied GPS MUST block location send (no fake Hangzhou/Shanghai coordinates); ungranted Mika Accessibility/ADB MUST guide pairing honestly.
- **UI/JNI Blocking Deadlock**: Removing JVM `synchronized(state.lock)` and releasing Rust `Mutex<Connection>` around `ureq` calls prevents slow network requests from freezing local SQLite reads or Compose UI responsiveness.
- **Stale Account / Sign-Out Data Leakage**: Sign-out MUST clear active bearer token, stop WS and `FabushiRemoteDeviceGateway`, bump `SessionRequestFence`, and return cleanly to `TelegramAuthWizardScreen` with zero stale chats visible.
