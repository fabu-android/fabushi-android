# 性能、内存、响应与资源预算

## 测量设计

采用实际发布 variant 与正式 ABI，在低/中/高性能参考设备分别记录型号、Android/API、刷新率、内存、温度、电量、电源模式、网络和预热条件。同一脚本重复运行，报告中位数、p95、样本数与方差；模拟器只用于定位，不代表真机发布性能。

测量 cold/warm startup 到可交互与 runtime-ready 两个时间、会话切换、长历史滚动、输入首帧、Agent 首 token（分离服务器耗时）、取消确认、工具/bridge 延迟、媒体上传/解码、ASR real-time factor、内存峰值、JNI handle/observer 数、CPU、后台唤醒、流量和电池。记录空闲/长任务/并发任务/低内存情境。

## 初始工程预算

本轮不把未测数值伪装成承诺。P1 在选定参考设备建立基线并固定可执行预算：帧时间按设备刷新率、启动/导航/取消 p95、内存硬上限、最大并发/事件队列/附件缓冲/模型资源。预算及合理阈值必须先进入 Spec，再在 CI 设 gate，不能测试后移动阈值使其通过。

硬约束不等待性能基线：UI thread 不做网络/大文件/数据库迁移；队列与缓存有限；Activity 重建不会无限增 observer；取消关闭录音/解码/连接；日志输出有界；存储清理只清缓存和任务拥有的文件。

## 测试场景

至少覆盖万条消息滚动、大字体和键盘、长流式会话、多会话并发、重复打开关闭 Mini App、百次 bridge 取消/重建、录音转写循环、网络反复切换、后台前台循环、低空间和内存压力。用 Android 官方 tracing/benchmark 方法及 native profiling 在 Actions 驱动的测试设备执行，分析真实卡顿/泄漏而不是只看平均 FPS。

变化超过预算时说明回归的责任路径、trace、修复和新证据；无法获得真机时保留 performance blocked，不以截图流畅代替。
