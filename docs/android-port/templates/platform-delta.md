# 平台差异评审模板

每份记录必须把“桌面实现机制”与“用户需要的产品效果”分开。

填写 delta_id、相关 responsibility_ids、Desktop SHA/path/symbol、桌面机制、用户效果、Android 适用系统/API、系统限制的官方出处及复核日期。不能把开发困难、尚未实现、没有测试或不喜欢某功能当成平台不适用。

写明候选本机替代、选择方案、执行位置、权限与隐私差异、离线行为、被拒权限后的 UI、撤销与取消、后台/进程死亡恢复。需要远程执行时，必须有显式配对授权及 unavailable 状态；不能让用户误以为操作在手机本机完成。

如果某机制确实无意义，例如桌面托盘或 DMG 公证，记录 Android 对应通知/导航或签名/分发责任；不会因此删除原用户目标。确实无对应产品效果的非适用项必须经独立审查批准，保留理由与证据。

最后给出 Kotlin/Rust 目标、测试场景、真实设备/系统、运行证据、已知限制、reviewer 与批准日期。缺少任一产品替代效果或证据时维持 blocked/mapped，不标 verified。
